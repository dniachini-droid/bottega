# What memory should be, before any of it is built

## What it does

Answers the questions nobody has answered about memory, with evidence, and
writes them down where a later session can read them. It builds no memory. It
produces one research page and a recommendation the owner can decide on.

## Survey the field first, then answer

Before the five questions, gather **what is actually being used and
recommended by the people leading this work** — not only what is written on
the open internet. Name the approaches, several of them, and say where each
comes from and what evidence stands behind it.

Then answer the five questions against that survey, rather than from first
principles.

*Why: the five questions below each have an obvious answer that sounds
sensible and has been tried and abandoned elsewhere. The point of looking
outward first is to find out which of the obvious answers are the abandoned
ones.*

## What done looks like

- **`docs/research/MEMORY.md` exists**, following the convention in
  `docs/research/README.md`: research is reference, not authority, and every
  claim is marked as read directly or taken only from a search summary.
- **It names several real approaches**, with where each comes from and what
  evidence supports it — a survey, not one idea.
- **It answers these five questions**, each with evidence and a
  recommendation:
  1. **What makes a session write a note?** Every lesson, or only a mistake
     that actually recurred? This is the question that decides whether memory
     stays lean or fills up in a week.
  2. **What does a note look like?** Enough shape to be searchable and
     prunable; not so much that writing one is a chore.
  3. **What is the cap, as a number?** Not "capped" — a figure, with its
     reason.
  4. **Does a session read all its notes, or search them?** The vision says
     plain text search first, structure second, embeddings never until a real
     question fails without them.
  5. **Who prunes, when, and how is a stale note recognised?** The clear-out
     is decided "from day one"; nothing says who does it.
- **It states what it could not establish**, plainly. The containers here
  could not reach most academic sources when the earlier research was done;
  if that happens again it is recorded, not smoothed over.
- **It says what it recommends, in one place, in plain words** — so the owner
  can say yes or no without reading the whole page.

## What is out

- **Building any of it.** No memory file, no rule in `AGENTS.md`, no change to
  any skill or agent. *Why: the vision says memory gets built when a session
  actually repeats a mistake, and that has not happened yet. This is the
  homework, done before it is needed, so that when it is needed the decision
  is not made in a hurry.*
- Changing either 10,000 limit.
- The check before a commit, Zibaldone, and the rename.

## The constraint that shapes every answer

Memory is read by a session, so under the counting merged today it is charged
against the limits. A building session sits at **7,968 tokens of 10,000** —
about **2,000 tokens, or roughly 8,000 characters, of room.** That is memory's
size limit and it already exists. Any recommendation that does not fit inside
it is not a recommendation, it is a wish.
